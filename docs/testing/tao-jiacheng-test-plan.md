## Scope

This document covers feeding, the first-clear rewards for both campus challenges, duplicate-claim prevention, sample green points, local-save persistence after refresh, and basic page use. It also proposes three small gameplay improvements for Qin Tian to consider. Qin Tian remains responsible for implementation, integration and final acceptance. No other member's contribution is completed or attributed here.

This submission is a complete test plan, with source-derived expectations and one limited AI-assisted observation of the live welcome page. It is not a completed playtest report. No personal manual gameplay by Tao Jiacheng, participant study, feedback collection or measured completion rate is claimed. No local game, build command or automated test suite was run for this document; no new runtime was installed.

Water durations, fees and green points are examples. They do not establish real water savings, and minutes cannot directly be converted into litres saved. The tree plaque is a virtual composite preview, not formal adoption, a physical installation or school approval. Guardian names and progress are local to a browser, not synchronised between devices.

Documentation only; no game code, assets, dependencies or deployment changes.

### Deterministic challenge procedures

- **Photo procedure P:** Open Challenges, then Start puzzle (or Play again for a completed challenge). With the default layout (or after Shuffle), swap positions **1 and 2**, then **5 and 6**, then **7 and 9**. Positions are numbered left to right, top to bottom, starting at 1. Each swap means click the first tile and then the second. Expect the final board to show 9/9 in place after three swaps. Shuffle restores this same source-defined arrangement; it does not reset the first-clear reward flag.
- **Pipe procedure W:** Open Challenges, then Connect pipes. From the fresh pipe layout, click pipe **3 twice**, **4 once**, **5 once**, **6 three times**, and **9 three times**, leaving all others untouched. Then click Let it flow. This derives from the source rotations and RULE-09 solution: route **4 -> 5 -> 2 -> 3 -> 6 -> 9**, exiting down from pipe 9. It is a planned UI procedure, not an executed solution. Do not repeat these rotation counts on an already rotated board; use a fresh fixture when required.
